# @gambrel/compiler

Finds your route files, generates the manifests, and builds the server and browser bundles. It does not handle requests. For the folder conventions, see [Routing and layouts](./routing.md).

## Discovery

```ts
import { buildRouteTable, discoverRoutes } from '@gambrel/compiler'

const table = await discoverRoutes('/app/src/routes')
table.routes   // route records sorted by id
table.sources  // every page and layout: id, kind, file, serverFile
```

`buildRouteTable(files, routesDir)` does the same from a list of relative file paths and does no I/O. The result does not depend on the order of the files.

Route ids are `page:/<folder>` and `layout:/<folder>`, with groups included: `page:/users/[id]`, `layout:/(marketing)`.

All convention problems are collected into one `CompilerError`, with a `problems` list naming each file or folder. They are: unsupported file names, server files without a component, invalid group names, invalid patterns, pages resolving to one URL, a missing routes directory and a directory without pages.

## Generated files

`generateRoutes({ root, routesDir?, outDir? })` writes three files into `.gambrel/` and returns the names it changed. Unchanged files are not rewritten.

| File                 | Contents                                                      |
| -------------------- | ------------------------------------------------------------- |
| `routes.ts`          | `routes`: the route records                                   |
| `manifest.client.ts` | `routes` and `components`. Never references a `.server` file. |
| `manifest.server.ts` | `routes`, `components` and `hooks`                            |

```ts title=".gambrel/manifest.client.ts"
// Generated by @gambrel/compiler. Do not edit.
import type { AnyRouteComponent } from '@gambrel/router'
import layout_0 from '../src/routes/layout.tsx'
import page_1 from '../src/routes/page.tsx'

export { routes } from './routes.ts'

export const components: ReadonlyMap<string, AnyRouteComponent> = new Map<string, AnyRouteComponent>([
  ['layout:/', layout_0],
  ['page:/', page_1]
])
```

Generation is deterministic. `generateModules(table, outDir)` returns the same text as strings and `writeModules(modules, outDir)` writes them. Add `.gambrel/` to `.gitignore`.

## Building

| Function                                | Does                                                                                                                                            |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `buildApp({ root, config?, mode? })`    | Generates the manifests, empties `outDir`, builds the browser and server bundles from separate entries, writes the manifests in `dist/manifest` |
| `buildClient({ root, config?, mode? })` | Regenerates the manifests and rebuilds only the browser bundle                                                                                  |

`mode` is `'production'` (default) or `'development'`. Both return `{ config, table, outputs }`, where `outputs` lists every output file.

Before the browser bundle is built, a guard stops the build if its imports reach a `*.server.ts` file, `@gambrel/ssr`, `@gambrel/bun`, `@gambrel/core`, `@gambrel/compiler`, or a `bun:` or `node:` module. The message names the importing file. This does not depend on tree-shaking.

## Configuration

`defineConfig`, `loadConfig(root)`, `resolveConfig(root, config?, mode?)` and `validateConfig(value)` handle `gambrel.config.ts`. The options are listed in [Configuration](./configuration.md).

## Errors

`CompilerError` (convention, configuration or build problems, with `problems`) and `RouteConfigError` (from the router, for invalid patterns and ids).
